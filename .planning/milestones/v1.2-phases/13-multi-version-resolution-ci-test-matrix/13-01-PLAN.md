1. Initialize script header with strict POSIX error handling and canonical repo root resolution:
   - Shebang `#!/usr/bin/env bash`
   - `set -euo pipefail`
   - `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd -P)"`
   - `REPO_ROOT="$(cd "$SCRIPT_DIR/.." && pwd -P)"`

2. Implement ephemeral sandbox workspace management with signal traps per D-05:
   - Create isolated temporary directory: `TEMP_DIR="$(mktemp -d)"`
   - Define `cleanup()` function:
     ```bash
     cleanup() {
       local exit_code=$?
       echo "[verify_consumer] Cleaning up ephemeral workspace: $TEMP_DIR"
       rm -rf "$TEMP_DIR"
       echo "[verify_consumer] Exiting with status $exit_code"
       exit "$exit_code"
     }
     trap cleanup EXIT INT TERM
     ```
   - Guarantees zero leftover scratch files, zero git status pollution, and zero repository lockfile mutations even on early exit or interrupt.

3. Define helper function `run_archetype(name, extra_deps)` per D-05, D-06, and D-07:
   - Creates project root `$TEMP_DIR/$name` and entrypoint directory `$TEMP_DIR/$name/lib`.
   - Generates consumer `pubspec.yaml`:
     ```yaml
     name: consumer_$name
     description: Ephemeral consumer resolution simulation for $name
     publish_to: 'none'
     environment:
       sdk: ">=3.0.0 <4.0.0"
       flutter: ">=3.10.0"

     dependencies:
       flutter:
         sdk: flutter
       fl_network_inspector:
         path: $REPO_ROOT
     $extra_deps
     ```
   - Generates consumer entrypoint `lib/main.dart` importing and referencing the public facade per D-07:
     ```dart
     import 'package:flutter/widgets.dart';
     import 'package:fl_network_inspector/fl_network_inspector.dart';

     void main() async {
       WidgetsFlutterBinding.ensureInitialized();
       await NetworkInspector.initialize();
       assert(NetworkInspector.isInitialized);
     }
     ```
   - In a subshell `(cd "$dir" && flutter pub get && dart analyze --fatal-infos lib/main.dart)`, executes real PubGrub dependency resolution followed by strict static analysis to prove zero compile-time errors or missing symbol definitions.

4. Define and invoke the 4 representative consumer archetype scenarios per D-06:
   - Archetype 1 (`modern`): Default contemporary Flutter consumer with empty `$extra_deps`.
   - Archetype 2 (`legacy_floor`): Pinned lowest allowable dependency bounds:
     ```
       dio: 5.2.0
       share_plus: 11.0.0
       intl: 0.18.0
       sqflite: 2.2.0
     ```
   - Archetype 3 (`mid_tier`): Realistic mixed-version consumer:
     ```
       dio: ^5.4.0
       http: ^1.2.0
       sqflite: ^2.3.0
     ```
   - Archetype 4 (`strict_localization`): Flutter localizations consumer validating SDK constraint coexistence:
     ```
       flutter_localizations:
         sdk: flutter
     ```

5. Output clear banner logging: `echo "=========================================================="` and `echo " SUCCESS: All 4 consumer archetypes resolved cleanly!"`.
6. Make script executable: `chmod +x tool/verify_consumer_resolution.sh`.

   - `set -euo pipefail`
   - `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd -P)"`

   - `cd "$REPO_ROOT"`

2. Implement Step 1: Packaging Boundary Verification via `flutter pub publish --dry-run` per D-09 and MATRIX-03:
   - Execute `flutter pub publish --dry-run`.
   - Asserts exit code 0 and verifies zero packaging warnings or archive boundary violations.
   - Echo confirmation: `[verify_pana] Dry run passed with 0 warnings!`.

3. Implement Step 2: Ensure `pana` CLI Availability per D-09:
   - Check if `pana` is available in PATH via `command -v pana`.
   - If missing, check if `dart pub global list | grep -q pana`. If missing, activate via `dart pub global activate pana >/dev/null`.
   - Export `$HOME/.pub-cache/bin` to `PATH` so `pana` binary is immediately executable in the current subshell.
   - Fall back to invoking `dart pub global run pana:pana` if the bare binary is not discovered.

4. Implement Step 3: Execute Pana Scoring Analysis and Score Extraction per D-10:
   - Run pana capturing JSON report:
     ```bash
     PANA_BIN="pana"
     if ! command -v "$PANA_BIN" >/dev/null 2>&1; then
       PANA_BIN="dart pub global run pana:pana"
     fi
     PANA_JSON="$($PANA_BIN --json . 2>/dev/null || true)"
     ```
   - If `$PANA_JSON` is empty or pana failed, inspect exit status and provide actionable diagnostics per D-12 (e.g. pub.dev reachability warning or raw stdout).
   - Extract granted points and max points directly from the JSON payload to avoid the `--exit-code-threshold` inversion pitfall (13-RESEARCH.md §Pitfall 1):
     ```bash
     GRANTED_POINTS=$(echo "$PANA_JSON" | grep -o '"grantedPoints":[0-9]*' | head -1 | cut -d: -f2 || echo "0")
     MAX_POINTS=$(echo "$PANA_JSON" | grep -o '"maxPoints":[0-9]*' | head -1 | cut -d: -f2 || echo "0")
     ```
   - Print `[verify_pana] Pana Score: $GRANTED_POINTS / $MAX_POINTS points`.
   - Evaluate against the strict 140-point threshold per D-10:
     If `[ "$GRANTED_POINTS" -lt 140 ]`, echo error message indicating the score fell below the required 140 point floor, output raw pana report for debugging, and `exit 1`.

5. Echo success banner: `[verify_pana] SUCCESS: Packaging and quality verification passed (Score: $GRANTED_POINTS / $MAX_POINTS)!` and exit with code 0.
6. Make script executable: `chmod +x tool/verify_pana.sh`.
