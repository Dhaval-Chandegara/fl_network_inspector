<objective>
Deliver real-time debounced search, quick-filter chips, advanced modal filter sheet, and multi-criteria sorting for the network inspector listing screen. Implement a persistent Material 3 `SearchBar` with a 300ms reactive debounce querying URL, method, status code, and payload text. Build a horizontal quick-filter chip bar and a modal bottom sheet for multi-parameter filtering (methods, status code ranges, min/max duration, date range). Add an AppBar sorting popup menu supporting newest, oldest, fastest, slowest, and status code order.

Purpose: Provide developers with rapid traffic isolation tools to filter and locate specific network transactions within large batches without UI stutter or memory leaks.
Output: Search bar component with clear action, horizontal filter chips bar, modal filter sheet, sort popup menu, integrated listing screen, and automated widget test suites.
</objective>

| User Search Input → Database Query | Search strings typed into SearchBar pass to SQLite repository |
| Filter Sheet Inputs → RecordFilter | Status code, duration, and date ranges parsed into query filters |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03 | Denial of Service | SearchBarView / InspectorViewModel | medium | mitigate | 300ms `Timer` debounce cancels outstanding timer before new queries fire, and explicit `_searchDebounceTimer?.cancel()` in `dispose()` prevents memory leaks and CPU thrashing during rapid keystrokes (D-54). |
| T-04-04 | Input Validation | FilterBottomSheet / DatabaseQueryBuilder | low | mitigate | Parameterized `RecordFilter` query builder uses bound `whereArgs` preventing SQL injection; numeric status codes and durations are bounds-checked before dispatch. |
| T-04-SC | Tampering | pubspec dependencies | high | mitigate | Package legitimacy gate verified for all UI dependencies (04-RESEARCH.md). |
</threat_model>
